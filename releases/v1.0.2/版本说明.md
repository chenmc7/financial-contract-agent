## v1.0.2 — 使用体验修复

**只改展示层**：3 个文件全部在 `static/`，Python、接口、数据结构、金融计算零改动。
`pytest` 仍为 47 passed。

| 编号 | 问题 | 改法 |
|---|---|---|
| UX-01 | 提示条遮挡右上角状态栏，错误提示看不见 | `#toast-wrap` 的 `top: 24px → 76px` |
| UX-02 | 同页「金额待复核」与「合同金额 ¥2000万」自相矛盾 | 交易下拉显示取「交易级 ?? 合同级 principal」，`value` 仍是 `transaction_id` |
| UX-03 | 同一合同可同时选为版本比对的新旧两版 | 新增 `lockDiffPickers()`，另一侧已占用的卡片置灰禁用 |
| UX-04 | 风险分与性价比分方向相反且无说明 | 文案补「（越低越安全）」 |
| UX-05 | 契约监控默认空表无录入引导 | 增加录入提示；输入框加 `placeholder`（不改空值判定） |
| UX-06 | 解析状态英文 `SUCCESS`，`DOCX · DOCX` 重复 | 状态映射中文；页注去掉重复前缀 |
| UX-07 | 字段表「状态」列被挤成竖排 | 第 5 列 `104px → 128px` + `white-space: nowrap` |
| UX-08 | 合同卡片缺字段时信息行不对齐 | 缺 `principal` / `annual_rate` 补 `—` |
| UX-09 | 导航 `Scenario Compare` 被截断 | 侧栏 `232px → 252px` |

验证：Playwright 自动化断言 **12/12 通过**；详见 `修复确认.md`。

## v1.0.1 — 后端缺陷修复

| 编号 | 缺陷 | 修复前 | 修复后 |
|---|---|---|---|
| 1 | 财务期间被当成数组下标 | 倒序录入时用最旧一期判断契约状态 | 按 `label` 解析排序，返回 `period_order` / `latest_period` |
| 2 | 交易投影不校验业务角色 | 12 亿授信额度被当本金 | 角色白名单，拒绝投影并给出业务原因 |
| 5 | SQLite 连接未关闭 | Windows 下 DB 文件被占用 | `_conn()` 改为 contextmanager |

测试：38 → 47，全部通过。
